# 6510 / 6502 Programming Reference

The C64's CPU is a MOS 6510: a 6502 core plus the 6-bit I/O port at `$00/$01`.
Instruction set and timing are identical to the NMOS 6502.

## Addressing modes and cycle costs

| Mode | Syntax | Bytes | Cycles |
|---|---|---|---|
| Implied / Accumulator | `inx`, `asl` | 1 | 2 |
| Immediate | `lda #$10` | 2 | 2 |
| Zero page | `lda $10` | 2 | 3 |
| Zero page,X / ,Y | `lda $10,x` | 2 | 4 |
| Absolute | `lda $1000` | 3 | 4 |
| Absolute,X / ,Y | `lda $1000,x` | 3 | 4 (**+1 if the index crosses a page**) |
| Indexed indirect | `lda ($10,x)` | 2 | 6 |
| Indirect indexed | `lda ($10),y` | 2 | 5 (**+1 on page cross**) |
| Relative | `bne label` | 2 | 2, +1 if taken, +2 if taken across a page |
| Indirect | `jmp ($1000)` | 3 | 5 |

Read-modify-write (`asl`, `lsr`, `rol`, `ror`, `inc`, `dec`) costs 2 more than the read:
zp 5, zp,x 6, abs 6, abs,x 7. `abs,x` RMW always pays the page-cross cycle.
`jsr` 6, `rts` 6, `rti` 6, `pha`/`php` 3, `pla`/`plp` 4, `brk` 7.

## Flags

`N V - B D I Z C`. `sec`/`clc`/`sei`/`cli`/`sed`/`cld`/`clv` set and clear them.

- `adc`/`sbc` use **and update** carry — `clc` before the first `adc`, `sec` before the
  first `sbc`. Forgetting this is the most common arithmetic bug.
- `sbc` subtracts `1 - carry`, so carry **set** means no borrow.
- Decimal mode (`sed`) affects `adc`/`sbc` only. The KERNAL IRQ does not clear it —
  `cld` at the start of any program that might inherit it.
- `cmp`/`cpx`/`cpy` do not modify the accumulator. After `cmp`: carry set = A >= operand
  (unsigned), zero set = equal. `bcc` = "less than", `bcs` = "greater or equal".
- `bpl`/`bmi` test bit 7 of the last value loaded or computed — they are **not** signed
  comparisons on their own.
- `bit` sets N from bit 7 and V from bit 6 of the *memory* operand, and Z from `A & M`.

## Signed arithmetic

Values are two's complement. Negate a 16-bit value:
```assembly
    lda lo
    eor #$ff
    clc
    adc #$01
    sta lo
    lda hi
    eor #$ff
    adc #$00            // carry propagates from the low byte
    sta hi
```
Arithmetic shift right (divide by 2, sign preserved):
```assembly
    lda hi
    cmp #$80            // carry = sign bit
    ror hi
    ror lo
```
A plain `lsr` here turns negatives into large positives.

## Fixed point

8.8 fixed point (one byte whole, one byte fraction) is the standard way to get sub-pixel
motion. Add velocity to position low-byte-first and let the carry propagate:
```assembly
    clc
    lda x_frac
    adc vx_lo
    sta x_frac
    lda x_lo
    adc vx_hi
    sta x_lo
```
For 9-bit sprite X you need a third byte for bit 8.

## Pitfalls that bite on the 6502 specifically

1. **`jmp ($xxFF)` bug.** An indirect jump whose vector starts on the last byte of a page
   reads the high byte from the *start of the same page*, not the next page. Never place
   a jump vector at `$xxFF`.
2. **Branch range is -128..+127** from the instruction after the branch. Long loops fail
   to assemble with "jump distance is too far". Fix by inverting the branch over a `jmp`:
   ```assembly
       cpx #$08
       beq done
       jmp loop
   done:
   ```
3. **Page-cross penalties** in `abs,x` / `abs,y` / `(zp),y` break cycle-exact raster code.
   Align timing-critical tables so indexing stays inside one page.
4. **`inc`/`dec` do not affect carry**, so they cannot be chained for 16-bit increments.
   Use `inc lo : bne skip : inc hi : skip:`.
5. **Zero page indexing wraps within page zero.** `lda $f0,x` with X = `$20` reads `$10`,
   not `$0110`.
6. **`(zp),y` needs the pointer wholly in zero page**; `(zp,x)` wraps in zero page too.
7. **The stack is only 256 bytes** at `$0100-$01FF` and wraps silently. Deep recursion or
   unbalanced push/pull corrupts it.
8. **`rts` jumps to address+1** — this is what makes the "rts trick" (push `addr-1`) work,
   and what breaks naive jump tables that push the real address.
9. **`brk` is a 2-byte instruction**; the return address skips the byte after it.
10. **NMOS `nop`, `lax`, `slo` etc.** ("illegal" opcodes) are real and stable on the 6510,
    and Kick Assembler assembles them by default (`.cpu _6502`). They are fine on real
    hardware and in VICE, but avoid them unless the cycle or byte saving matters.

## Self-modifying code

Common and legitimate on the C64 for speed (an absolute address patched at runtime beats
`(zp),y`). Label the operand and write to it:
```assembly
    lda #<table
    sta src + 1
    lda #>table
    sta src + 2
src:
    lda $ffff, x        // operand patched above
```
It is unsafe only if the code might run from ROM/cartridge or be re-entered from an IRQ
between the patch and the use.
